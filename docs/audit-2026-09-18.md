# Audit 2026-09-18 — code vs documentation

Snapshot of the repository at `39fa96f` (v1.8.0). Like the previous audit
documents, this file is **not** updated afterwards: it records what was known
on this date. Fixes are tracked in issues.

## Method

Every document in `docs/`, `CLAUDE.md`, `README.md`, `ROADMAP.md`,
`CHANGELOG.md`, `SECURITY.md` and the deployment files (`docker-compose.yml`,
`Dockerfile`, `Makefile`, `config.yaml.example`, `.env.example`, CI workflows)
was read end to end and checked claim by claim against `adso/` and `tests/`.
Eight parallel read-only auditors, one per disjoint group of documents, each
told to read whole functions rather than grep hits, and to report anything
they could not verify. The consolidated findings below were then triaged and
the code findings marked **verified** were reproduced by hand in a temporary
vault before being listed as bugs.

## 1. Code findings

Severity reflects impact on the running bot. "Verified" means reproduced in
this session; "hypothesis" means read from the code and not executed.

### 1.1 Verified

**C1 — Every note the bot writes triggers a second, unsuppressed watcher
callback (medium).**
`create_note` reserves the final `.md` with `O_CREAT|O_EXCL`
(`vault_writer.py:328-341`, inotify `IN_CREATE` on a visible `.md`) and then
`_atomic_write_sync` does `os.replace` (`FileMovedEvent`). The watcher enqueues
both (`vault_watcher.py:84-87`, `:105-127`) and its 2 s dedup turns the second
into a trailing-edge fire. `bot.py:125-127` discards the `bot_written_paths`
marker on the **first** callback only, so the second one runs
`_reindex_external_note` (an extra Gemini embedding call) and
`git_backup.notify(stem)` (a second, differently labelled entry in the same
commit, debounce re-armed). Reproduced: one `create_note` under a live
`VaultWatcher` yields two `on_external_change` callbacks at +0.01 s and
+2.01 s. Rewriting an existing file yields exactly one, so this is specific to
the placeholder + replace sequence of `create_note`. Production evidence: the
log of 2026-09-17 14:00 shows `Nota creada`, `Embedding indexado`, then
`Embedding indexado` + `Reindex externo completado` 3 s later for the same
note. Affects `_cb_confirm`, `reclassify_inbox`, `_notify_index_written`.
Docs that state the invariant: `docs/decisions-log.md:40,44`, CLAUDE.md
"Syncthing bidireccional", comment at `capture.py:1073-1078`. Existing
`test_on_moved_*` tests feed synthetic events and cannot see this.

**C2 — 14 unit tests open real TCP connections to
`generativelanguage.googleapis.com` (medium, test infrastructure).**
The report generators call `_llm_synthesis` unconditionally
(`reporters.py:434,548,689,803`); it builds a real `genai` client and swallows
every exception (`reporters.py:313-315`). `tests/unit/test_reporters.py` has
zero `patch(...)` calls, so with network these tests send a real HTTPS request
with `GEMINI_API_KEY=dummy`, receive a 4xx and pass because the failure is
silent. Reproduced with a socket-blocking plugin: 14 attempts, all from
`test_reporters.py` (`TestScopeReport` ×3, `TestIdeasReport` ×2,
`TestHealthReport` ×5, `TestReadingQueue` ×3) and
`test_audit_block_cd.py::TestScopeReportDates::test_mixed_aware_and_naive_dates`.
The suite still passes with sockets blocked, which also shows the synthesis
path is never asserted by those tests. There is no network guard of any kind
in `tests/conftest.py` or `pyproject.toml`. Contradicts CLAUDE.md:368,
`docs/testing.md:583,729` and `.github/workflows/ci.yml:31-33`.

**C3 — `reindex.time` fires in UTC, not server local time (medium).**
`bot.py:366-371` passes a naive `time` to `run_daily`; PTB 21 hardcodes the
scheduler timezone to UTC unless `Defaults(tzinfo=...)` is set, and nothing in
`adso/` sets it. Reproduced: with `TZ=America/Argentina/Buenos_Aires`
exported, `app.job_queue.scheduler.timezone` is `UTC`. `"03:00"` therefore
runs at 00:00 ART. Harmless today, but the same path is the template for the
weekly report (`"12:00"` would fire at 09:00). Contradicts
`docs/configuration.md:73,106` and `config.yaml.example:9,71` ("hora local del
servidor"). Listed as backlog in `docs/improvements-2026-07.md` ("`run_daily`
naive time"), so known but undocumented as a limitation in the user-facing
config docs.

**C4 — `create_note` does not default `status` (medium).**
`vault_writer.py:529-534` `setdefault`s `date_created`, `date_modified`,
`source`, `media_type` but not `status`; `docs/frontmatter-schema.md:87-93`
promises a per-type default (`active` / `pending` / `raw`). Reproduced:
`create_note({"title": "x", "type": "reference"}, ...)` writes a file with no
`status:` line. Reachable input: Gemini or Groq returning `"status": ""` for a
`[Nota]` capture (legal: `_validate_capture_payload` at
`llm_schema.py:440-443` turns `""` into `None` and `_clean_frontmatter` drops
`None`). The cron path guards this (`jobs.py:157-158`); the interactive
`_cb_confirm` path applies `STATUS_ON_CONFIRM` only for
`pending-classification` notes coming from `/clasificar`
(`capture.py:1047-1048`). The comment at `capture.py:686-690` ("el default lo
resuelve el resto del pipeline") describes code that does not exist.

**C5 — Startup does not validate `VAULT_PATH`; it creates it (medium).**
`docs/architecture.md:1089` says "Si el path no existe o no es un directorio,
el bot falla con error claro y no arranca". `ensure_vault_structure`
(`vault_writer.py:1142-1151`) is `mkdir(parents=True, exist_ok=True)` and
`bot.py:51` calls it with no existence check. Reproduced: a non-existent
nested path is created with the five folders, no error. A typo in
`VAULT_PATH` or an unmounted bind starts the bot against an empty vault;
GitBackup reports `not_repo` and the watcher watches the wrong directory.

**C6 — An unknown project name from the LLM silently creates a project folder
(low, design).**
`_resolve_dest_dir` builds `01-Projects/{project}` from the LLM value;
`_safe_component` blocks traversal only; `create_note` does
`mkdir(parents=True)`. Nothing compares `fm["project"]` against
`_get_existing_items`. Reproduced: vault with `01-Projects/tesis/`,
`create_note({... "project": "Tesis "})` → `01-Projects/Tesis/` created next
to `tesis/`, without `_index.md`. `docs/architecture.md:940,220` and
`docs/obsidian-vault-structure.md:153-154` say the bot "pide autorización
para crearlo". The only guard is the user reading the "Destino:" line of the
preview.

**C7 — `03-Resources/*.md` is excluded from structural scans but not from the
semantic index (low).**
`_ALWAYS_EXCLUDE` lives in `vault_search._scan_vault`; `embeddings.should_index`
checks `exclude_dirs`, `_index`, root and sync-conflict but never
`03-Resources`. Reproduced: `should_index(vault/"03-Resources"/"x.md", vault)`
is `True`. A `.md` dropped there is embedded by the nightly reindex and the
watcher and appears in `/buscar` while `/reporte`, tag discovery and
`find_by_property` never see it. CLAUDE.md (#58 bullet) presents the two
exclusions as the same shape.

**C8 — `_download_to_tmp` leaks a 0-byte temp file when the Telegram download
fails (low).**
`input.py:104-121` creates the file with `NamedTemporaryFile(delete=False)`
and then awaits `download_to_drive`. If that raises, the exception propagates
before `tmp_path` is assigned in the caller (`handle_audio:426`,
`handle_document:707`, `handle_photo:777`), so the callers' `unlink` never
runs. Any `TimedOut`/`NetworkError` during the download leaks an inode on the
RPi tmpfs. One fix in the helper covers all three callers.

### 1.2 Hypotheses (read, not executed)

- **C9** `_apply_note_corrections` (`capture.py:627-631`) returns handled for
  `prioridad urgente` without changing anything or telling the user; the
  preview is re-rendered unchanged. Already listed as open in
  `docs/audit-2026-07-31.md` block H.
- **C10** `/status` prints the watcher as `activo` after `observer.start()`
  failed: `vault_watcher.py:192-200` swallows the exception and sets
  `_observer = None`, `WatcherStats` has no running flag, `commands.py:92-95`
  checks only that the object exists. Backlog item in
  `docs/improvements-2026-07.md:443-444`.
- **C11** `scripts/check_vault_sync.py:37` uses `DEFAULT_EXCLUDE_DIRS` and
  never loads `vault.exclude_dirs`, so `make check-sync` reports notes the bot
  deliberately skips as missing embeddings. Its docstring claims the rules
  are "taken from the bot".
- **C12** `ADSO_UID`/`ADSO_GID` are documented as freely settable
  (`docs/installation.md:124-127`, `.env.example`, CLAUDE.md) but the image
  only creates uid/gid 1000 (`Dockerfile:26`, comment: SSH fails without a
  passwd entry) and `chown`s `/app/data` to it. A different uid breaks the
  git push, the whisper cache and ChromaDB. The Dockerfile also has no
  `USER`; the drop to non-root comes only from compose `user:`.
- **C13** An image sent as a *file* (`.png/.jpg/.webp` document) never gets
  the OCR/Vision keyboard: it goes through `_dispatch_document`
  (`input.py:585-671`) → "Formato no compatible", with the
  `documents.max_size_mb` (20) limit instead of `image_max_mb` (8).
  `docs/architecture.md:460` says the user chooses with buttons.
- **C14** `_detect_manage_keywords` fires on `archivar/borrar/eliminar/
  renombrar` (`constants.py:124-130`) but `build_intent_keyboard` renders
  buttons only for `project`/`area`, so "borrar la nota vieja" gets
  `[Cancelar] [Tarea] [Nota]` with no manage button **and no
  `[🔎 Buscar en el vault]` row** (`input.py:301-306`).
- **C15** `build_preview` (`keyboards.py:99-113`) sends `project`, `area`,
  `status`, `priority`, `due_date` and the joined tags into Telegram HTML
  without `_esc`; only title, links and snippet are escaped. Exposure is
  gated on `_to_kebab` stripping `<`/`>`. `docs/audit-2026-07-31.md:380-394`
  (E4) claims the escape was added; block H at `:916-917` correctly lists it
  as open.
- **C16** The `Stopwatch` line of `_classify_and_preview` is emitted on all
  four `return` paths but there is no `try/finally`: an exception from
  `_get_existing_items` or `render_with_keyboard` exits without it. CLAUDE.md
  says "por todos los caminos".
- **C17** Only the arXiv path adds the `paper` tag (`capture.py:1464-1466`);
  the PDF path strips an LLM-proposed `paper` via `_TYPE_TAGS`
  (`llm_schema.py:265-268,484`) and never re-adds it, so PDF papers carry no
  `#paper`. Reports identify papers by `read_status`. CLAUDE.md: "Los papers
  se identifican por tag `#paper` y/o presencia de campos académicos".
- **C18** `_INJECTION_PREVIEW_WARNING` for extracted content (PDF, OCR,
  Vision, arXiv) is computed *after* `classify()` returns
  (`capture.py:448`, `:1491`); only typed text is checked before the LLM
  call. `docs/security.md:321` says "antes de enviar". Effect is identical
  (nothing blocks), wording is wrong.
- **C19** `priority` default `medium` (CLAUDE.md:199) is enforced only by the
  prompt; if the LLM returns `priority: null` for a task nothing fills it.
- **C20** `keywords` extracted from PDF papers (`document_extractor.py:301-376`)
  go to the LLM but are never rendered in the preview
  (`input.py:876-889`); CLAUDE.md:76 says the preview shows them.

## 7. Decisions for the user

Not bugs; the docs and the code disagree and either side could be right.

1. **Manage operations** (D1): implement archive/rename/delete, or remove them
   from CLAUDE.md, the modes table and the "acciones destructivas" rule.
2. **Unknown project from the LLM** (C6): validate against existing items and
   fall back to Inbox, or document that the preview's "Destino:" line is the
   only guard.
3. **`03-Resources/*.md` in the semantic index** (C7): add the folder to
   `should_index` to match `_ALWAYS_EXCLUDE`, or document the asymmetry.
4. **Images sent as files** (C13): route image documents through the
   OCR/Vision keyboard, or document that only photos get it.
5. **Reclassify cron writes without preview** (D9): keep, but state the
   exception in `docs/security.md` §8 and `SECURITY.md`.
6. **`VAULT_PATH` auto-creation** (C5): fail on a missing path, or keep the
   auto-create and fix architecture.md.
7. **Stale audit documents**: per the standing rule they are not edited; the
   improvements doc (`docs/improvements-2026-07.md`) is a living backlog and
   should be brought up to date.
