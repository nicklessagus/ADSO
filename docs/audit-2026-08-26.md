# Audit 2026-08-26

Full functional audit of ADSO: every user-facing feature reviewed module by
module, plus an audit of the **production vault** (90 notes) and of the
documentation against the code.

> **Language note.** This document is in English following the repo-wide
> decision of 2026-08-26 that all *new* material (symbols, docstrings, new
> documents, issues) is written in English. Pre-existing Spanish documents,
> code and tests are not retro-translated; they are corrected in Spanish so no
> file ends up bilingual.

---

## Method

Seven review passes, one per functional cluster, each verified against the real
code rather than against documentation:

| Cluster | Modules |
|---|---|
| Capture and callbacks | `handlers/capture.py`, `handlers/callbacks.py`, `keyboards.py`, `constants.py` |
| Input and media | `handlers/input.py`, `transcriber.py`, `document_extractor.py`, `arxiv_client.py` |
| LLM, config, security | `llm_client.py`, `llm_schema.py`, `config.py`, `security.py` |
| Vault | `vault_writer.py`, `vault_watcher.py`, `vault_search.py`, `vault_cache.py` |
| Embeddings and retrieval | `embeddings.py`, `knowledge_query.py`, `handlers/query.py` |
| Commands, reports, jobs | `handlers/{commands,manage,reports,jobs}.py`, `reporters.py`, `tasks_client.py`, `bot.py`, `bot_utils.py` |
| Data and docs | production vault (90 notes) + `README.md` and `docs/` |

**Every reported bug is backed by a failing test.** The rule applied throughout:
write the reproducer, watch it fail for the documented mechanism, apply the fix,
watch it pass. Reproducers were written *before* any fix and verified with
`--runxfail` so that a test failing because of a bad mock could not be mistaken
for a real defect. Bugs still open keep their reproducer marked
`xfail(strict=True)`: the suite stays green, and the day the bug is fixed the
test turns XPASS and `strict` turns that into a failure, forcing the marker to
be removed in the same commit as the fix.

**One false finding, caught by the tests.** 40 of the 41 audited mechanisms
reproduced exactly as described. The fortieth — an apparent duplication bug in
`find_tasks` — turned out to be deliberate behaviour: the fix broke an existing
integration test whose fixture and comment document the intent explicitly. It was
reverted and reclassified as a design question (#61), with characterization tests
pinning the current behaviour. That is the mechanism working: a "bug" inferred
from a dead variable did not survive contact with the suite.

---

## Results

- **40 bugs** confirmed and reproduced; **39 fixed** in this pass (35 from code
  review, 5 of the 6 surfaced by the real vault). The one left open is #53
  (duplicate detection misses uploaded files): it needs a design decision on
  what to key the dedup on, so it ships as an issue rather than a rushed fix.
- **~100 reproducer and counter-case tests** added across seven files
  (`tests/unit/test_audit_2026_08_*.py`). Every `xfail` marker is gone: each bug
  was fixed in the same pass, and its reproducer is now a regression guard.
- **59 issues** opened: one per bug, plus grouped improvement issues.
- **48 documentation drift points** corrected and **14 undocumented features**
  documented.
- Coverage **76% → 84%**; suite **770 → 896 tests**, all green.

Counter-cases matter as much as reproducers here: several fixes are one-line
guards that would be easy to over-apply (deleting *no* wikilinks instead of only
valid ones, degrading *every* invalid type instead of only the ones the user
already chose). Each such fix ships with a test asserting the neighbouring
correct behaviour still holds.

**#53 is the one confirmed bug left open.** `save_resource` already computes the
SHA-256 and already detects that two uploads are the same file — the information
needed to deduplicate exists and is discarded. What is missing is the decision of
what to key on (content hash vs `source_file`) and how it interacts with the
existing `source_url`/`doi` lookup, so it is filed rather than patched.

Auditing the docs against the code also surfaced #61 (`find_tasks`), described
above — filed first as a bug, corrected to a design question once the existing
suite showed the behaviour was intended, and #62 (`tipo` correction on a task),
found in the post-fix verification pass and fixed with the rest.

## What the vault audit found

The vault is **structurally healthy**. Verified clean: zero corrupt YAML, zero
frontmatter keys outside the whitelist (no `handler`/`content` ever reached
disk), zero numeric titles, zero `None` destination fields, zero folder↔frontmatter
mismatches, zero duplicate titles/`source_url`/`doi`, zero broken embeds, zero
write artifacts, zero Syncthing conflicts on notes, and a ChromaDB index that
matches the 81 indexable notes exactly.

What it did surface, beyond the six bugs above, is tracked in #60: four notes
with schema violations (two of them hand-edited in Obsidian, confirmed against
git history), 14 broken wikilink targets predating the git history, 1.5 MB of
orphaned resources, and a set of taxonomy decisions the data makes visible —
`05-Archive/` empty after five months while whole projects were deleted rather
than archived, 16 notes sitting in the Inbox that no cron will ever touch
(none carries `pending-classification`), and a tag vocabulary where 57% of tags
are used exactly once.

## Documentation

`docs/architecture.md` carried the bulk of the drift (20 points), including a
whole documented flow that does not exist (generic web-link extraction) and
several keyboard layouts that no longer match `keyboards.py`. Corrections and
the 14 previously undocumented features — among them `/help` and `/reset`, paper
duplicate detection, the correction-prefix mode, the local relative-date parser,
`vault_cache.py`, the latency instrumentation and the model regression harness —
were applied to the documents where they belong.

Test and coverage figures in `docs/testing.md` were stale (623 tests documented
against 786 collected); they now reflect a measured run.

## Follow-up

Every bug above is fixed and guarded by its reproducer. What remains open are the
**improvement** issues (#36–#51, #57, #58, #60) and the one design question
(#61) — each with a proposed implementation and proposed unit/coverage/regression
tests.

The convention that came out of this audit is now in `CLAUDE.md`: a bug found but
not fixed on the spot gets a reproducer marked `xfail(strict=True)`, so the suite
stays green while the day someone fixes it the test turns XPASS and `strict`
forces the marker out in the same commit. Two rules make it work — verify with
`--runxfail` that the test fails for the documented mechanism and not a broken
mock, and pair it with counter-cases, because most of these fixes are one-line
guards that are easy to over-apply.
